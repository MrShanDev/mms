# v1-20260402 插件安装校验、版本入库与启动加载

## 流程

1. **上传安装**（`POST /system/pluginHost/install`）  
   - 读取 JAR 内 `plugin.json`，结构与宿主兼容性校验（与原先一致）。  
   - **通过后**写入 `mms.plugin.root-dir`。  
   - **再写入库表** `sys_plugin_version`（该 `plugin_id + version` 记一条，`is_active=1`；同插件其它行置 0）；并 **upsert** `sys_plugins`（无行则插入市场展示行）。  
   - 若入库失败：**删除刚写入的该版本磁盘目录**并返回错误。  
   - 成功：**全量 reload**。

2. **启动加载**（`PluginHostRunner` → `loadAll`）  
   - 若库表 **`sys_plugin_version`** 在租户 `000000` 下**无任何行**：与旧版一致，对磁盘做**全目录全版本**扫描。  
   - 若**已有行**（已纳入管理）：  
     - 先仅加载 **`is_active=1`** 的 `plugin_id + version`（磁盘路径须存在）；  
     - 再对磁盘上 **库中仍无任何版本记录的 plugin_id 目录**做「未纳管插件」**全版本**扫描（兼容历史只有磁盘、未跑过安装入库的环境）。

3. **卸载**（`POST /system/pluginHost/uninstall`）  
   - 先删磁盘，再 `onUninstallDiskFinished` 同步删/减库表版本行，最后 reload。

4. **版本回切**（`POST /system/pluginHost/activateVersion`，body：`pluginId`, `version`）  
   - 校验磁盘对应 `lib` 下存在 JAR；更新库表仅该版本 `is_active=1`；reload。

## 数据表

- 执行 `script/db/increment_20260402_sys_plugin_version.sql`。  
- 插件注册当前固定租户 **`000000`**（与默认 `sys_plugins` 上架数据一致）。

## 前端

- 详情中展示「库 table 激活版本」「已登记版本」，并提供 **回切版本 + 切换并重载**。

## 桥接

- `PluginHostDbBridge` / `PluginHostDbBridgeImpl`：宿主与 `mms-system` 库表之间的唯一衔接；`PluginLifecycleManager` 通过 `ObjectProvider` 可选注入。
